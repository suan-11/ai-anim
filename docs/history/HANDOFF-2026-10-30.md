## 0. 一分钟版本

用户拿来一个 76 MB 的本地素材包（**341 条代码动画风格提示词 + 193 张静帧**），问「引擎下一步干什么」。
我把 341 条全部解析、193 张静帧全看了，用一个子代理做了逐条能力盘点，结论是：

> **65% 的条目不是能力问题，是封装问题；而真正的结构性短板是「引擎画不了面」。**

于是这一轮做了三件事（都是**纯增量**，不改任何已交付画面）：

| # | 做了什么 | 规模 | 为什么是它 |
|---|---|---|---|
| ① | **填充面 `src/core/fill.js`** + `LineBatch` 三个方法 | 248 行 + 37 行 diff | 素材包 26 条参考实现里 **11 条**要 `beginPath + arc + fill`，而引擎只有描边。这是 23 个模板看起来都是「线 + 矩形」的**图元原因** |
| ② | **仪器视图 `src/kit/views.js`**（八种成像） | 484 行 | 素材包里「介质」是横跨十个组的唯一公共维度；落地了 BACKLOG 1-11 |
| ③ | **九套版式风格 `src/style/panels.js`** | 198 行 | 原 21 套里**浅底纸面只有 `paper` 一套**，连做两支必撞脸 |

风格包 **21 → 30 套**，镜头模板仍是 23 个（**没有加新模板**，见 §5）。

## 1. 这一轮做了什么（事 / 位置 / 验证）

### ① 填充面：引擎第一次能画「一块面」

| 项 | 位置 | 验证 |
|---|---|---|
| 扫描线数学（偶奇规则带洞 / 圆 / 扇环） | `src/core/fill.js`（248 行，纯函数） | `tools/test-fill.mjs` **39 项** |
| `LineBatch.fillPoly / fillCircle / fillSector` | `src/core/gl.js`（+37 行） | 同上 + 夹具 `tasks/_fill-lab/` |
| kit 再导出 `polySpans / circleSpans / sectorSpans / ringEdges / crossingsAt` | `src/kit/index.js` | 导入自检 |
| 回归 | `tools/test-fill.mjs`（挂 `unit:fill`） | 39 项，含**方向断言** |
| 文档 | `docs/COOKBOOK.md` **§17**、`AGENTS.md` §3.5 一行 | — |

**为什么走扫描线而不是三角化**：`LineBatch` 只会画线段（胶囊），而 `fillRect` 本身就是「一行行短线段」。
把多边形 / 圆 / 扇区也变成「水平跨度」再交给线段批，就**不需要改顶点着色器、不需要新的 draw call**，
颜色仍然是线性 HDR、抗锯齿仍是线段批那套，也不破坏「每帧是 t 的纯函数」。代价是每行一次采样（`step` 可调）。

### ② 仪器视图：同一张画面，八种介质

`src/kit/views.js`（484 行）。入口是 `instrumented(ctx, { mode, cell }, draw)`，另有 `renderCapture` / `applyView` 分开用。

| mode | 画面 | 覆盖的素材包条目 |
|---|---|---|
| `halftone` | 半调网点印刷 | L29、O19、O22 |
| `ascii` | 字符画（5×7 点阵、11 级） | E3、L39、O18、O28 |
| `dither` | 1-bit Bayer 抖动 | K28、X17、L36 |
| `posterize` | N 级平涂（丝印 / Riso） | L28、L11、K36 |
| `thermal` | 冷热色带 | L11、L44 |
| `pixel` | 最近邻像素化 | V13、X13、K28 |
| `crt` | 扫描线 + 荫罩 + 桶形畸变 | X14、V12、L39 |
| `engrave` | 雕版排线（线宽表现明暗） | L30、L31、O10、O3 |

## 2. 踩掉 / 发现的坑（**这一节最值钱，别跳**）

### 2.1 填充面的两个真 bug（都是「画面会错但不报错」）

1. **扇区在「这一行两端都在角度区间外、但中间在区间内」时返回整行**
   —— 饼图里被裁的那几行整行涂黑，缺了个口子，而**在深色底片上看着像设计**。
   修法：这一支也做成两次二分（找首、尾两个分界），而不是直接 `return [-outer, outer]`。
2. **`clipArc` 用 `cos(a) * outer` 反推 x** —— 点在圆上时半径是 `sqrt(outer² + d²)`，不是 `outer`。
   错了饼图被压成花瓣。修法：按 x 二分求角度分界，不在角度域反推坐标。

> 这两条都补进了 `tools/test-fill.mjs` 的断言（尤其是**角度方向**：0 = 右、π/2 = **下**、π = 左、3π/2 = 上）。
> 方向写反画面照样出，只是整块镜像 —— 人眼极难当场发现。

### 2.2 仪器视图的三个坑

1. **字符画的字模表手写顺序不单调**：`=`（10 点）排在 `o`（8 点）前面 ⇒ 中灰底被印成一片近白，
   整张图消失。修法：**运行时按实际着墨点数稳定排序**，并断言严格不减。
2. **极性写反**（`dither` 的黑白、`thermal` 的底色）：深色底片上「看着还挺像」，做成显式常量 `SCREEN_POLARITY`。
3. **引擎 `GLSL_COMMON` 的 `hatch()` 不是「墨覆盖率」**，而是「暗度附加值」，直接当墨用会得到
   **整屏斜纹的反相版画**。排线只能自己写（`fwidth` 抗锯齿 + 线宽 0.46 封顶）。

### 2.3 惊到我的两条判断（都来自子代理，我复核过）

- **「引擎画不了面」是真的**：`LineBatch` 公开方法只有 `seg / polyline / circle(描边) / rect(描边) / fillRect / tick`，
  `fillRect` 是一行行矩形。这解释了 23 个模板的同一种味道 —— **不是审美选择**。
- **「65% 是封装问题」成立**：A 换皮 127 + B1 只差成像 60 = 221/341。

### 2.4 `hashes beat` 的假报警（**重要，别重复踩**）

跑 `hashes beat --baseline` 时它报 **6/11 帧不一致**。我**没有直接 `--accept`**，而是把自己的改动 `git stash` 掉，
在**干净的 HEAD** 上复现 —— **同样 6/11**。真相：

- `src/core/audio-analysis.js` 与 `tasks/beat/audio/demo-loop.analysis.json` 在 **2026-10-30 18:17** 被改过（那轮修 bpm 4% 偏差，BACKLOG 1-60）；
- `out/beat/hashes.json` 的基线是 **2026-10-24** 的。
- 差异内容是**数字读数** `-0.92 → -0.93`、`1.08 → 1.07`、`3.08 → 3.07`，以及波形 / 圆环相位各移一点 —— 全是节拍网格变了。

**处理**：确认与本轮无关后，带 note 重新结清：

```sh
node scripts/anim.mjs hashes beat --accept --note "…bpm 修复后基线过期，与 fill/views/panels 无关…"
```

> ⚠ 这个教训要传下去：**`hashes` 报红时，先用 `git stash` 在干净 HEAD 上复现一次再决定 accept。**
> 直接 accept 会把「别人改坏了」和「基线本来就过期」两种情况混成一笔账。

## 4. 还没做（下一个会话从这里接，按性价比排序）

> 这一节与 [REFERENCE-style-pack-capability.md](../REFERENCE-style-pack-capability.md) §3 的能力缺口表**同源**，但只列我核过的。

### 4.1 最划算的一件事：`style.view`（子代理的头号建议，我没做）

把 `src/kit/views.js` 的八种成像从「场景里的一次函数调用」提成**风格包字段**：

```js
export default { style: { name: 'h-blue', view: { mode: 'halftone', cell: 6 } } }
```

- 插在「整段合成完 → post 之前」，**默认 `off`**（不动任何已有画面）；
- 覆盖素材包 B1 那 60 条里的一大批（单一模式直接对上的：网点 4 + 字符画 5 + 像素 7 + CRT 3 + 排线 5 + 热敏 1）；
- 工程量：一个 Pass 接线（约 40 行）+ 风格包加 1 个字段 + 默认 off。

⚠ **我没有做它，是因为它动的是「整片默认观感」这条路** —— 一旦有人给某套风格开 `view`，那套风格的每一支片子都变。
这需要用户拍板（「我要不要一个『整片印成半调』的风格」），不是工程判断。**先问用户再动手。**

### 4.2 胶片磨损（`post.weave` / `flicker` / 划痕）

覆盖 17 条（G1 G2 L2 L6 L16 L34 L53 O4 O16 O26 O47 O56 O66 O83 O84 O86 O91）。
纯 post 数学，约 40 行，`grain` / `vignette` / `halation` / `tint` 都已存在。
**代价最小、覆盖第二多**，而且和 4.1 互不冲突。

### 4.3 N 版套印（`halftone` 扩多版）

18 条（L28 L29 L32 O8 O11 O19 O22 O25 O31 O36 O40 O42 O43 O54 O55 O64 O88 K36）。
网点面积正比于墨量的数学已在 `views.js`，扩成 N 版 = 加一层循环 + `misregister` 偏移，约 120 行 GLSL。

### 4.4 剩下按复用度排（详见能力盘点 §3）

| 能力 | 覆盖条数 | 代价 |
|---|---|---|
| 剪纸 / 纸艺层叠（层 + 硬投影 + 撕边） | 20 | 中，约 200 行 |
| 手绘笔迹（可变宽笔 + 逐笔生长） | 17 | 中，约 250 行（`lineart` + `boil.js` 已占七成） |
| 彩墨 / 水彩湿边 | 12 | 中，约 200 行 GLSL（只能做「像」，做不到「真」） |
| 像素精灵（调色板量化 + 8–12fps） | 7 | 小（`post.pixel` + `stickerShot` 已有） |
| 木刻 / 铜版多方向排线 | 5 | 小，约 80 行 |

### 4.5 母题抽取（判据写在 `REFERENCE-style-pack.md` §4）

三条同时成立才抽：① 是**数学对象**不是氛围；② ≥3 条素材包条目同源；③ 抽完只写参数。
候选：**字散再聚**（A5 / M3 / M25 / M38）、**图表生长**（F1 / L40）、**关系图**（F2 / L5）。
另有两个**原语**值得单独抽：`textPoints()`（字形 → 点集，A5 / B3 都要）、marching squares（C3 等高线）。

## 5. 刻意没做的（免得以后又被翻出来）

| 没做 | 原因 |
|---|---|
| **不加新镜头模板** | 子代理的盘点说 B3（新几何 / 3D）只有 38 条，且多数是 Three.js 内容层（缺的是内容不是能力，`makeThreeShot` 已有）。加模板是「一支片子一个」，填充面是「所有片子都用」 |
| **不做油画 / 水彩真实晕染 / 粘土定格 / 角色动画**（共 46 条 C 档） | 这是扩散模型与画家的赛道。用 GLSL 追油画必然输给一张生成图。我们该借的是**配色与构图**，不是假装能画出来 |
| **不复刻 O 组 98 种介质** | 那 98 条不是风格库，是 **98 份分镜脚本**（每条都以同一个主角 `Clawd` 演出，中位 3 个镜头、总长中位 2.5 秒）。其中 60 条有空镜可借。可行路线是**用已有 8 种成像 + 30 套风格重演那 98 个分镜** —— 分镜是结构可以搬，介质是身份搬不动 |
| **不动 `src/shots/` 的模板背景** | 模板刻意自带整帧背景（`chart` 用 `P.bone` 当纸、`P.ink` 画柱，见 `src/shots/chart.js` 注释）。浅底风格配图表会「反相」—— 那是设计意图不是 bug。要改就得手写场景 |
| **没有增加 AGENTS.md 的内容** | 只加了**两行**带触发条件的指针（§3.5 的填充面与成像），因为文件余量只剩 2274 B。按文件头的写入判据，查表内容一律进 `docs/` |

## 6. 需要用户拍板的两件事

1. **`style.view` 要不要做**（§4.1）—— 它会让「某套风格的每一支片子」都自动换介质，属于观感层面的决定。
2. **H / K / Z 三组 65 条里 63 条正文只有一句话**（「粗线条，网点，速度线，对比强」），且只有 H1 / M1 / Z5 三张静帧。
   这 65 条**只能当名字列表用**。要落地得**向素材包作者要截图**，否则做出来就是猜配色。
   （这一条我没法替用户决定 —— 是「要资料」还是「就这么放着」。）
