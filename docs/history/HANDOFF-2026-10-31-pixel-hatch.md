## 1. 像素精灵（1-67）：四条硬约束，五条只有出图才看得见的

`src/kit/pixel.js` 给的是**按像素画**的能力，不是「给画面加个像素滤镜」：

| 件 | 是什么 | 不这么做会怎样 |
|---|---|---|
| `paletteOf()` | 五张内建调色板（gameboy 4 色 / nes 8 色 / amber 4 色 / pico 8 色 / bit1 2 色）+ 自定义色表 | 颜色一多，块就不读了 |
| `ditherQuantize()` | 在**最近两色**之间按 Bayer 二选一 | 按亮度找色阶会把饱和的橙摊成灰；用渐变则是现代滤镜 |
| `SPRITES` / `spriteOf()` / `drawSprite()` | 14 个内建精灵（heart star coin key diamond bot ghost tree skull arrow block dot slash cross），`#` 画 | 逐字画 8x8 精灵要写 64 条线 |
| `pixelText()` / `FONT5x7` | 68 个字符的 5x7 点阵（A–Z / 0–9 / 标点 / ♥★▲▼▶→←•） | 真字体放大到 1080p 会糊，缩到 4K 会碎 |
| `snapTime(t, 12)` | 12fps 的**时间台阶** | 60fps 平滑 = 现代；跳台阶才是「算力不够」的唯一可见证据 |
| `pixelGradient()` | 抖出来的渐变（同色格自动合并成一条线） | 逐格画 240×135 = 32400 条线，直接打满 LineBatch |

模板 `shot('pixel')` 是一整屏成品：抖出来的天空 + 日/月/星 + 地面纹理 + 一串走动的精灵 + 边框 + 页脚带。
参数：`palette` / `cell` / `crawl` / `rows` / `style` / `kicker` / `title` / `sub` / `footer`。

### 1.1 五条只有出图才看得见的（模板里都踩过，注释与单测钉着）

| # | 坑 | 现象 | 解法 |
|---|---|---|---|
| ① | 瓦片重采样用了**点采样** | 快块之间随机跳变，中文标题**碎成一地** | 先降到 `cols × 4`，再在 JS 里做 4×4 方框平均 |
| ② | `readPixels` 是**自下而上**的 | 整块画面**上下颠倒**（机器人跑到天花板上） | 用到 `lines` 前翻 y：`(rows - 1 - y)` |
| ③ | 天空跨了 3/4 张色表 | 天空变成**一道彩虹** | 只跨两档，中间全靠抖动 |
| ④ | 文字画在压栅格**之前** | 笔画被块平均抹掉，副标彻底消失 | 美术先压、文字后画；最后那次 `post.pixel` 取**半格**（整格会把 CJK 笔画 ≈ 字号/10 整根吃掉） |
| ⑤ | 两级栅格**相位不同** | 整屏浮着一层**斜纹摩尔纹** | `post.pixel` 必须与瓦片尺寸同相（同一倍数），不能随手取 0.5× |

**另一类**（不是坑，是像素画的语言）：抖动阈值要按**块**坐标取（按像素取 ⇒ 一块被撕成噪点）；
精灵与像素字要落在**整块**上（差半块 ⇒ 抗锯齿把边缘抹成灰）；台阶用**整片时间** `f.t` 而不是 `f.lt`
（用段内时间的话每次切段动作会卡一下）。

### 1.2 与 `post.pixel` 的分工（这一层存在的理由）

`post.pixel` 是事后降采样：颜色不受控、没有抖动、文字一起糊。
模板里两者都用了，但分工明确：**美术先自己压成整格色块（`squash`），文字最后再被 `post.pixel` 压一次** ——
于是中文与像素图落在同一格上，而不是互相毁掉。

## 2. 多方向排线（1-68）：按明暗**加方向**

`views.woodcut` 是第 9 种成像（`style.view: { mode: 'woodcut', cell: 22 }` 或 `instrumented(…)`）。

| 明暗 | 画什么 |
|---|---|
| 亮部（dark < 0.16） | 不起线（纸就是纸） |
| 中间调（≥ 0.16） | 第 0 层一道线 |
| 更暗（≥ 0.46） | 加第 1 层，交叉 |
| 暗部（≥ 0.72） | 加第 2 层，第三道 |

每加一层，那一层的线更细（0.9 / 0.75 / 0.6 px 半宽）—— 真实刻刀的第二道压在第一道的空隙里。

### 2.1 五条纪律（每条都是出图之后补的）

| # | 纪律 | 不这么做会怎样 |
|---|---|---|
| ① | 每层更细 | 三层叠起来立刻**饱和成实黑**，画面丢一大半 |
| ② | 层边界要抖（Bayer 进门槛） | 中间调上出现一块块「补丁」 |
| ③ | 线要断，**段要长**（约 9 格一段） | 3 格一段 ⇒ 出图是一排**点划线**，像传真 |
| ④ | 明暗取 **24 点黄金角螺旋**局部平均，半径跨整格 | 网格 / 单点采样与底图自带的周期（`fillRect` 行距、扫描线、网点）**拍频** ⇒ 整屏水波纹 |
| ⑤ | **线距 ≥ 22px**（低于会被夹住并写 warning） | 45° 线的周期投影 ≈ 间距/√2：12px ⇒ 8.5px，与行距凑成近整数比 ⇒ 整屏很宽的**次谐波横带**（看着像「油墨没推开」） |

> **可推广的一句**（这是这一轮最值钱的产出）：
> 任何「按亮度重新画线 / 画点」的介质，动笔之前先问两句 ——
> **我采样的尺度比底图的最小特征大吗？我的周期与底图周期成整数比吗？**
> 两个答案只要有一个是「不」，出图就是一层人造纹理，而 `check` 三点采样永远绕得过去。
>
> 另外两条调版时补上的（都写进了 COOKBOOK §16.4）：
> **文字要阳文不要阴文** —— 排线是整帧成像，深色字落在浅纸上会被三档排线刻成一片麻
> （探针实测），真版画的字是"深色版上的浅色字形"；**新层刚出现时的宽度不是 0** ——
> 纯 pow 的话第二层在刚过门槛的区间里只有零点零几像素，中间调上等于没有第二层
> （出图看起来仍然只有一道线），现在按 `0.22 + 0.78 × pow(t, 0.85)` 从细线长起。

### 2.2 与 `engrave` 的取舍

`engrave` 只有一个方向、全靠线宽 —— 暗部会粘成实黑，但**便宜**（1 遍采样 vs 24 遍）。
画面本来就很淡、只想「像一张老书插图」时用 `engrave`；需要**刻痕的层次**时用 `woodcut`。

| 给像素层加「精灵与场景的碰撞 / 物理」 | 那是游戏引擎的活。像素只是**介质**，这支引擎要的是「看起来像那台机器算的」，不是可玩 |
