## 1. 一眼总览

**341 条 = 127 条换皮 + 60 条只差成像 + 62 条要材质原语 + 38 条要新几何 + 46 条不追 + 8 条是空壳。**

四个必须先说的事实，它们决定了后面每一条的判断：

1. **这个包的"分辨率"极不均匀。** 72 条正文不到 200 字（H 11、K 全 38、Z 14、M 9），正文就是"粗线条，网点，速度线，对比强"这种一句话 —— **它们的真实信息量等于一次调色板 + 字体选择，不是一份可实现的规格**。反过来 L 全 59 条（中位 12429 字符，最长 20501）和 V 全 15 条（平均 6948 字）是**完整的施工图**：本质 / 不是什么 / 材料 / 颜色逻辑 / 字体 / 运动 / 镜头语法 / 声音 / 陷阱 / 变体空间，十节齐全。所以"341 条"不等于"341 个工作量"，其中约六成只在"选风格"这一层有用。
2. **O 组不是风格库，是 98 份分镜脚本。** 98 条**每一条**都以同一个主角 `Clawd` 演出（"Clawd 扮斯嘉丽""Clawd 扮基宇"），每条的"成片里的分镜"是 1–9 个带秒数的镜头（中位 3 个，全片总长中位 2.5 秒）。它们是**一支合集片的 98 个镜头**，不是 98 种能套在任何内容上的风格。其中 **38 条每个镜头都有 Clawd**，另 60 条至少有 1 个无角色镜头 —— 那 60 条的空镜部分才是我们能借的。
3. **"介质"是横跨十个组的唯一公共维度。**（下面全是关键词命中，不是人工判定，会略高估）135 条提到颗粒、143 条提到描边 / 轮廓、97 条提到渐变、52 条提到硬阴影、27 条提到纸纹、26 条提到网点、25 条提到套色错位。**它不是某一类片子的需求，而是每支片子都缺的那一层。**
4. **A–G 那 26 条参考实现有一半不能直接搬。** 9 条用 `+= v*dt` 累积状态（A1 A2 A5 B1 B2 B4 C3 D1 F1），3 条直接 `Math.random()`（D1 G1 G2）—— **画面在 A 档，代码一进引擎就破确定性**，改写成本 10–30 行/条。另有 11 条靠 Canvas2D 的 `beginPath / arc / fill` 铺面，而**我们的线批只有描边圆和 fillRect，没有填充多边形** —— 这是 A–G 暴露出的最常见实现差异（§3 第 4 行）。

- **21/26 是 A 档**（换皮或 ≤150 行）。真正卡住的只有 C1（湿边）、E2（纸边阴影）两处，它们都指向同一个缺口：**填充形状 + 柔边**。

- **9 条不可 seek、3 条不可复现**，但都是画面级的简单改写，不是能力缺口。

## 4. 做不了 / 不该做

**46 条判 C**（画家介质与角色动画 39 + 定格 / 实拍 7）。它们不是"技术上限够不到"，而是三个身份问题。

### 4.1 扩散模型和画家才能做的（39 条）

| 素材包条目 | 为什么不是我们的活 |
|---|---|
| **油画厚涂**：L20 O12 O39 O45 O48 O51 O62 O65 O89 K19，以及 O13 O14 O20 O24 O35 O37 O46 O53 O59 O61 O63 O69 O76 O93 各一种笔触介质（共 31 条 O + 4 条别处） | 厚涂的本质是**画家对每一笔的决策**：哪里刮刀、哪里堆颜料、哪里的棱受侧光。程序化只能生成"像笔触的纹理"，放大到 1080p 一眼是滤镜 —— 而我们的画面全是矢量锐边，纹理一糊就露馅。**没有一个"我们的场景"需要用油画来承载信息**，这才是真理由 |
| **水彩真实晕染**：K18 Z15 L18 O14 O24 O53 O63 O76 | 需要水膜仿真：颜料颗粒在纸纤维里沉积、湿画法回流、干后边缘积一圈深色。可以做"形似"（§3 第 7 行），做不出"真"。**但"形似"对科普片已经够用** —— 所以这 12 条里我判 12 条进 B2（§3 第 7 行），水彩本身一条都不进 C |
| **粘土定格**：K24 M31 | 手指印、布的纤维、每格之间道具被真的挪过一点点的位移。这是**物理道具摄影**，不是渲染 |
| **皮克斯式 3D 角色**：K25 L47 O38 | 绑定、肌肉、次表面散射、毛发。一个角色的制作周期是几周，我们一支片子是几小时 |
| **角色表演**：L45 L46 L47（+ O 组 38 条每镜头都有 Clawd） | 走位、口型、表情、眼神。观众对"人"的容错是零：一个僵硬的表情比一张干净的关系图难看十倍 |

### 4.2 实拍 / 物理素材（7 条）

L54 后室（新怪谈实拍）、M11 人生循环（同一个人一生）、M13 手绘定格第一人称、M32 竖屏快节奏 POV、K24 粘土、K25、M31 粘土 MV。

**共同点**：画面里有一个"被拍摄的真实东西"。我们的引擎没有摄影机、没有镜头、没有景深之外的真实感来源。

### 4.3 我们不该追的四条理由

1. **追介质会输给扩散模型，追结构不会。** 一条 4K 的油画质感，扩散模型 30 秒出图；一张"32 个节点、6 条边、每个读数都有出处"的关系图，扩散模型出不来。我们的护城河是**确定性 + 可复算**，不是笔触。
2. **确定性契约与"每次不一样"天然对冲。** `render(t)` 是纯函数、子帧并行、可任意 seek —— 这一条换来预览 = 成片、可中断重渲、真运动模糊。而"笔触要有生命"意味着每一帧都得不一样。两者不可能同时成立，而**放弃前者等于放弃整个引擎**。
3. **21 套风格包的"一眼认得出"会被稀释。** 每套包的识别度来自"配色 + 字体 + 母题 + 后处理基线"四件事的**克制**。再塞一层笔触纹理，四件事全被盖住，21 套会塌成 1 套"有纹理的"。
4. **投入产出比是负的。** §3 第 1–4 行（介质层 + 多版 + 胶片 + 填充形状）加起来约 300 行，覆盖 95 条；一条"真油画"约 2000 行 + 无限调参，覆盖 0 条能承载信息的画面。

**一句话：我们做"确定性排版 + 程序化介质"，不做"AI 生成画"。前者是引擎，后者是画家。**

## 5. 讲解结构（M 系列）里对我们最有用的 5 条

M 系列 40 条里有 **8 条是空壳**（M14 M15 M16 M17 M26 M35 M39 M40，正文 0 字），剩下 32 条里 **20 条是 A 档** —— 它们是**结构**，不是**画面**，所以不消耗渲染能力，只消耗"编排能力"。按对我们（讲解 / 科普片）的用处排：

### ① M21 原理拆解（"3–5 步，前一步的结果变成下一步的开头"）

- **要什么能力**：**元素接力** —— 上一步的产物不是淡出，而是**变成**下一步的输入（位置 / 形状 / 颜色连续）。以及"合并看全貌"这一拍需要一屏装下前面所有产物。
- **我们最接近的一层**：`src/kit/carry.js` —— `morphRect`（按下的东西变成结果）/ `hop`（主体跳到下一个槽）/ `gather`（一群元素收拢成标志）/ `zoomThrough`，四个函数正好是这条提示词的逐字翻译；再加 `makeShot` 的 `enterOffset` 就有"从反方向落位"。
- **缺什么**：`carry` 现在只是纯函数词表（`tools/test-carry.mjs` 离线单测），**没有镜头模板**把它用起来。把这四个函数包成一个 `explain` 模板是最省的一步。

### ② M23 五幕讲解（问题 → 是什么 → 怎么用三步 → 例子 → 结尾卡）

- **要什么能力**：**段落骨架 + 时长分配**。它不给画面，只给"五段、每段一个职责"。
- **我们最接近的一层**：`src/kit/info.js` 的 **`infoShot`**（标题 / 面板底 / 侧标注 / 出处 / 页脚 / 错峰全包，场景只写 `draw(ctx, rect)`）+ `seq / cut` + `narration.mjs` 的 `SCENES` 表（旁白是唯一时间源）。
- **缺什么**：**没有"五幕"的现成骨架**。但这条的价值不在模板，在于它验证了我们的分层是对的：`infoShot` 就是"一幕"，五幕 = 五个 `infoShot` + `carry` 衔接。

### ③ M20 时间线 / 历史（轴往前走，到节点放大讲、再缩回继续走）

- **要什么能力**：**一台连续相机 + 节点的"放大 → 停留 → 缩回"**。注意"缩回"要求相机能回到同一位置 —— 我们天然满足，因为相机是 `t` 的纯函数。
- **我们最接近的一层**：**`timeline` 模板**（横向事件轴 + 笔尖 + 节点弹出 + 事件名上下交替）+ `cameraPost(t, {zoom, center})`。
- **缺什么**：`timeline` 只做"沿轴前进"，不做"推近某一节点再回来"。加一个 `focusAt` 参数（节点索引 → `center` / `zoom` 关键帧）就是完整的 M20。

### ④ M4 一个元素串全片（"圆点不能瞬移，只能连续地动过去"）

- **要什么能力**：**跨段的元素连续性** —— 同一个东西在切点上必须还在同一条轨迹上。这是"像一支片子而不像幻灯片"的最强手段（AGENTS §4.5 的第 3 条"一个走完全片的母题"就是它）。
- **我们最接近的一层**：`worldPass` 的共享背景（切点两侧逐像素一致）+ `cameraAt(t)` 的全片摄影机 + `carry.js` 的 `hop`。
- **缺什么**：**没有"跨段主体"的登记机制**。现在每个场景各自画自己的圆点，位置对不上。最小实现：在 `task.config` 里声明 `motif: { at: (t) => [x, y] }`，`makeShot` 每帧把上一段的末位置作为本段入场的起点。

### ⑤ M2 纸感手写笔记（马克笔一笔一笔、手写字、每 1.5–2 秒一个新点子）

- **要什么能力**：**笔迹生长 + 手写体 + 节奏下限**。它把"节奏"写死在提示词里（1.5–2 秒一个点子），这正是 `lint-event-density`（最长静止 ≤3.5s）在做的事。
- **我们最接近的一层**：**`lineart` 模板**（弧长画线、笔尖光点）+ **`kit/boil.js`**（12fps 确定性抖动）+ `type.write` 的逐字入场。
- **缺什么**：**可变宽笔**（中心线 + 压力 → 轮廓多边形）。现在所有线都是等宽胶囊，一笔写出来的字看起来像印刷体加了抖动 —— 这是 §3 第 6 行。

> 备选第 6 名：**M33 从一个点拉远到宇宙**（多尺度推拉 + 最后一句话）。它是纯 `cameraPost` + 景深 + 一屏字的组合，成本最低、辨识度最高，但它不教"怎么讲"，只教"怎么收"。如果只能改一处，它排在 M2 后面。

## 6. 一句话结论

**只做一件事的话：把 `src/kit/views.js` 那 8 种成像从"场景里的一个函数调用"提成风格包上的一个字段（`style.view`，插在 post 之前、字幕之前，默认 off），同时给 `halftone` 加上多版套印、给 `post` 加上 weave / flicker / 划痕 —— 一件事、三个字段，把 B1 那 60 条整体落下来。它是唯一一件"装一次、之后每支片子都自动受益"的事：给所有讲解片补上一层"这东西是被某种介质记录的"质感底线，而不动任何已有画面的一像素。**

（排在它后面的第二件事是 §3 第 4 行"填充形状 + 柔边光斑"—— 那一条提升的是**上限**：让引擎第一次能画"面"而不只是"线和矩形"。）
