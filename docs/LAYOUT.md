# LAYOUT —— 版面纪律与「版面守门」

> 观众对钠那期视频（`tasks/sodium`）的反馈里有一条：**「有些动画元素相互遮挡害得我搞不清楚到底
> 要看哪个主体」**。这句话在产物上**可复现**（逐帧统计：一屏 4–6 个信息块、最多的段一帧 9 块、
> 单场景文字调用 14 处），而引擎当时**一条判据都没有** —— 亮度统计看不出"元素太多"，
> `check` 只管亮度 / 背景守门 / 非有限值 / 依赖令牌。
>
> 这份文档写两件事：**一条纪律**（每屏只让观众看一件事）与**它的机器判据**（`anim check` 的
> 「版面守门」那一段）。判据的代码在 `src/layout.js`（纯函数）+ `src/app.js` 的 `layoutRows()`
> + `scripts/anim.mjs` 的 `cmdCheck()`；离线单测 `tools/test-layout.mjs`（46 项）。

---

## 1. 纪律（写画面之前先定）

1. **一屏只有一个主体。** 观众看向哪里，是**你**决定的，不是他自己找的。
   这一屏要讲的那件事（图示 / 大数字 / 曲线）是主体，其余一切都得是**标注**。
2. **主体之外最多两块。** 页眉、说明条、脚注**不算**（它们是这一支片子的版式母题，见 §3）。
   超了就是「一屏多头」，观众会不知道该看哪个 —— 这正是钠那期的原话。
3. **读数一次只揭一个。** 同屏一次亮 6 个数，等于 6 个数都没被读进去。
   钠的 `glass` 段一帧 49 次文字绘制、合并之后 9 块 —— 判据会点名它。
4. **画面文字只放标注**（名词 / 数字 / 单位 / 出处），**句子交给旁白与字幕**。
   同屏两套完整句子就是观众说的"两条字幕"（`docs/CAPTIONS.md` 纪律 1、`lint-narration-dup`）。
5. **声明主体**：场景对象上写 `focus`（或时间线段上写），判据才知道"哪里是主体" ——
   不写不是"通过"，是**没判**（`check` 会进 `skipped`，`--strict` 下算失败）。

---

### 「主体区 0 块」有两种意思（2026-10-25 起读数会分开它们）

判据只数**文字块**，所以「主体区 0 块」本身分不清两件事：

| 画面 | 主体区 | 这一帧画了什么 | 新读数 |
|---|---|---|---|
| **主体是图形**（方波 / 格阵 / 波形，文字只是标注） | 0 块字 | 有矢量 / Pass | `0 块字（这一帧的主体是图形：N 次非文字绘制）` |
| 真的空屏 | 0 块字 | 一笔都没有 | `0 块字，而且**一笔非文字绘制都没有**` |

为什么以前看不出区别：《把信号拆开》（`tasks/spectrum`）每一段的主体都是图形，读数一直是
「主体区 0 块」—— 不报错（判据 ③ 在 0 块时恒成立），但看起来像"没画东西"。读数的判读在纯函数
`layoutVerdict()` 的 `focusNote` 里（`'graphics'` / `'empty'` / `'text'` / `'undeclared'` / `'unjudged'`），
打印在 `scripts/anim.mjs` 的 `focusReading()`，两处都被单测钉着。

那个量取自**同一本绘制账**（`gl.paint`，`src/core/gl.js` 的 `beginPaint()`）：

- **非文字绘制 = `paint.any` − `paint.other` − 文字层那一次合成**。
  `any` 是"真的提交过的每一次绘制"；`lines` / `full` 是它的子集（矢量批次 / 不透明全屏 Pass）；
  `other` 是引擎内部搬运（xform / 快照，不算画面内容）；文字层自己那一次 `comp.draw` 要减掉，
  否则"只写了几行字"的段会被算成画了图形。
- ⚠ `paint.text` 这个字段**从来没有人写过**（`beginPaint()` 初始化成 0 就再没动过）——
  它不是"文字绘制次数"，文字只有 `paint.blocks` 这一份。
- **它没有坐标**：这是**整帧**的读数，不是"主体区里面画了几笔"。接口名与打印措辞都按整帧写。

边界（诚实清单）：场景若一帧里 `comp.draw` 了不止一层，只减得掉 1 次 ⇒ 读数会偏高；
`render` 抛错的那一帧画的是**错帧卡片**，读数按"没判"处理（说 0 就等于说"这一屏是空的"）。
**这条读数不改变任何判据** —— 判据 ③（`maxInFocus`）在 0 块时本来就恒成立，`maxBlocks` 与
`maxOffSubject` 一个字都没动（`tools/test-layout.mjs` 有一条专门钉这个）。

### 标注可以合并成一行（`labelRow`）—— 判据 ② 数的是"看的地方"

**为什么**：判据 ② 数的是**观众要看向几个地方**，而它只能从文字块里数。`LOW` / `MID` / `HIGH`
三个标签**各站在自己的柱子上方**（y 不同）就是三块、三个入口；把它们合成一行就只是**一块**。
纪律本身没变（"一屏一个主体"），变的只是排版：一行读得完的标注，观众眼里本来也只有一处。

**怎么写**（定义在 `src/kit/layout.js`，也从 `src/kit/index.js` 出）：

```js
import { labelRow } from '../../../src/kit/index.js';

text.clear();
// 三个标签 + 一条说明 → 一块（记账 1 条、判据只数到 1）
labelRow(type, [
  { s: '波形', c: css(P.ash) },
  { s: 'LOW / MID / HIGH', c: css(P.signal) },
  { s: '2.4 s', c: css(P.ash) },
], L.x0, 985, { size: 21, family: 'mono' });

// 居中：x 是**整行中心**（宽度它自己量，不用你算 x - w/2）
labelRow(type, [{ s: '采样率' }, { s: '48 kHz', c: css(P.bone) }], 960, 420,
  { anchor: 'center', size: 24 });
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `items` | — | `[{ s, c }]`：文字 + 颜色（`c` 省略 = 用 `opts.color`） |
| `anchor` | `'left'` | `x` 是整行的左边 / 中心 / 右边（与 `writeLine` 同义） |
| `gap` | `'　·　'` | 分隔符（全角空格夹间隔号），可以换成 `' | '` 之类 |
| 其余 | — | 原样交给 `writeLine`：`size` / `weight` / `family` / `color` / `alpha` / `stagger` … |
| 返回 | — | 整行宽度（含分隔符与 tracking） |

**为什么它必须是"一次绘制"**：一块是 `src/core/text.js` 的 `noteText()` 记出来的 ——
**每次**真的画出字形的 `write` / `writeLine` 都往 `gl.paint.blocks` 里压一条。
所以 `labelRow` 把整行拼成**一个字符串**、只发**一次** `writeLine`：记账 1 条。
（`codeRow()` 是**每段一次**绘制、色块分明 —— 那是"一行代码"，不是"一屏要看的一件事"，
两者不互相替代；单测 `tools/test-layout.mjs` 钉着这两条。）

**什么时候不该合并**：

- **真的要让观众分两次读的读数就该分开揭晓** —— 纪律 3「读数一次只揭一个」说的是**时间**上的分开
  （先亮一个、再亮下一个），不是"永远只有一块"。合并不是把两件不同的事塞进一行。
- 两段标注**语义上没有关系**（一个是时长、一个是来源）时，硬合成一行会让读的人以为它们是一组。
- 需要**各自入场**（每段自己的 stagger / 颜色动画 / 发光）时用 `codeRow()` ——
  `labelRow` 是一次绘制，只有一套动画参数。

**一个诚实提醒**：`textGroups()` 是**按 y 单链聚类**的（`src/layout.js`），
同一基线上一字排开的三段**判据本来就只算一块**。所以"合并成一行"真正省掉的是
① 记账条数（n 次文字绘制 → 1 次）；② 标签**各站一处**（y 不同）时的块数与"看的地方"。
别把这两件事说成"一字排开就一定三块" —— `tools/test-layout.mjs` 里两条正反例都钉着。

## 2. 判据：`anim check` 的「版面守门」

```sh
node scripts/anim.mjs check <任务>            # 默认：只 warn，不改退出码
node scripts/anim.mjs check <任务> --strict   # 把这条路也变成门（退出码 1）
node tools/test-layout.mjs                    # 判据本身的离线单测（不需要 GPU）
```

**判据两条半**（都在纯函数 `layoutVerdict()` 里）：

| # | 判据 | 阈值 | 说的是什么 |
|---|---|---|---|
| ① | **一屏几块字** | `maxBlocks = 6` | 同屏的信息块太多（钠的 `glass` 一帧 9 块 / `cull` 8 块） |
| ② | **主体之外有几个「看的地方」** | `maxOffSubject = 2` | 「不知道要看哪个主体」的直接读数（不要求声明 focus） |
| ③ | **主体区里压着几块** | `maxInFocus = 2` | 「元素互相遮挡」—— **只在声明了 `focus` 的段才跑** |

**读数**（每个采样点一行）：`3 块（6 次文字绘制）  主体区 0 块字（这一帧的主体是图形：2 次非文字绘制）`
—— 后面那一句的三种写法见 §1（主体是图形 / 空屏 / 没声明）。

**「块」怎么算**（`textGroups()`）：把挨得近的文字合成一块再数。
判据不是"数调用次数" —— 右上那 6 个读数是 6 次调用、**观众看见的是一块**。
合并阈值**随字号缩放**（`min(gap, 较小字号 × 0.8)`，地板 12px）：
size 18 的读数行距 26px 会合成一块，size 96 的标题与下方 34px 处的读数**不会**被并进去。
（两版固定阈值都在单测里当场翻车过：36 把两行 size 24 的标签并了，28 又把读数并进了大字。）

**采样**：每段 15% / 50% / 85% 三个时刻（`--quick` 只采 50%），与逐段亮度守门**同一批渲染**
（`layoutRows()` 不渲染，读的就是那两帧留下的 `gl.paint.blocks`）。报告取**最挤的那一帧** ——
观众记住的是峰值，不是平均；同时给出"有几个采样点超限"。

**退出码**：与 `docs/BACKLOG.md` 1-19 同一条哲学 —— **默认只 warn，`--strict` 才进 errs**。
理由很实际：这套阈值是一条**新纪律**，现在每个任务都必然超限；让 `check` 默认非零退出，
`tools/regress-all.mjs` 会永久染红，反而没人看了。**交付自检跑 `--strict`**，日常回归跑默认。

## 2.5 几何判据（C1，2026-11-14）：字压字 / 出画 / 撞字幕

数量判据之外，`src/layout.js` 的 `geometryViolations()` 用同一本绘制账（聚类后的块 bbox）加三条几何判据，
接进 `layoutVerdict`，`check` 照常打印。**默认 warn，`--strict` 才进 errs**（off-frame 是 error 级）。

| 判据 | 口径 | 级别 |
|---|---|---|
| `overlap` 字压字 | 任意两块交叠面积 > 较小块的 **15%**（保留区里的版式字不参与） | warn |
| `off-frame` 出画 | 块的**锚点**越出画幅 `0..W / 0..H` | error |
| `off-safe` 越安全边距 | 成块内容字（size≥32）越出 `grid.pad`（保留区豁免） | warn |
| `caption-hit` 撞字幕 | 块与**此刻正在渲染的字幕**矩形相交（引擎 `_drawCaptions` 记 `lastCaptionRect`；没字幕不判） | warn |

**受控豁免**：任务/风格 `layout: { allowOverlap: ['标注', …] }` —— 块的 sample 文本含其中任一字符串，
该块就不参与 overlap 判。豁免要显式写清关掉了什么（与 RULES.md 的纪律一致）。

**假阳性校验后收紧的两处**（C1 验收要求，实测 demo/beat/pv-king）：
- `off-frame` 只判**锚点**越界，不拿 `x1>W` 判 —— 右对齐/居中字的锚点不是左上角、宽度是 sans 近似，
  拿右边缘判会在 beat 的 LOW/MID/HIGH 上刷假阳性。
- `off-safe` 只判 size≥32 的成块内容字 —— 贴边的计数器/角标（kinetic 的 079）是版式装饰，不是内容压边。

## 3. 声明主体：`focus`

三种写法，位置两处（**段上的优先**，同一支片子里某一段想换主体时不必改场景）：

```js
// ① 场景对象上（这一段的默认主体）
export default { id: 'chart', focus: 'center', render(ctx) { … } };

// ② 时间线段上（覆盖场景那一份）
cut(chart, { dur: 6, focus: { x: 480, y: 180, w: 960, h: 760 } }),

// ③ 配置档节点上（B 档同样支持 —— focus 是**时间线字段**，不是模板参数）
{ type: 'chart', values: […], dur: 5, focus: 'center' },
```

| 写法 | 含义 |
|---|---|
| `focus: 'center'` | 画面中心 **46% × 50%**（`CENTER_FOCUS`：左右各留 27%、上下各留 25%） |
| `focus: { x, y, w, h }` | 逻辑像素的矩形（左上角 + 尺寸） |
| `focus: { cx, cy, w, h }` | 给中心点 |
| 不写 | **没判** —— 判据 ③ 不跑，`check` 会在 `skipped` 里点名这一段 |

判据怎么用它（`focusOverlap()`）：一块字与主体区**重叠面积 ≥ 它自己面积的 50%** 才算"在主体区里"。
「主体」的定义是**图连通**的：落在主体区里的块 ∪ **最大的一块**，再把空间上连着的块并成一个
「看的地方」。所以一块读数组里的 6 个数**不会**互相算成"抢视线"（它们是一件事），
而它旁边隔开的那块字才算一次真正的"多了一个东西"。

### 版面母题保留区（`RESERVED_BANDS`）

页眉（y ≤ 11.5%H）与说明条 / 脚注（底边 ≥ 90%H）上的字是**这一支片子的版式**，
**既不算判据、也不算读数**。没有这条豁免的话，钠那种"每段都有页眉 + 说明条 + 脚注"的片子
**每一段都必然超限**，判据立刻变成噪声。三个带与 `src/kit/bands.js` 同源
（页眉 y≈92 / 说明条 y≈964 / 脚注 y≈1018，1920×1080 基准）。

## 4. 阈值可以按任务调

```js
// tasks/<任务>/task.config.mjs（顶层；也可以写进 style: { name: …, layout: {…} }）
export default {
  // …
  layout: { maxBlocks: 8, maxOffSubject: 3, gap: 24, minAlpha: 0.2 },
};
```

| 键 | 默认 | 含义 |
|---|---|---|
| `maxBlocks` | 6 | 一屏最多几块文字（含读数） |
| `maxOffSubject` | 2 | 主体之外最多几个「看的地方」 |
| `maxInFocus` | 2 | 主体区里最多几块 |
| `gap` | 28 | 合并成一块的**上限**（实际阈值 = `min(gap, 较小字号 × 0.8)`，地板 12） |
| `minAlpha` | 0.25 | 低于这个不透明度的绘制不算"占了一屏"（还没揭晓的字） |

`check` 会把当前阈值打出来（`（上限 6；主体之外 ≤ 2）`）—— 阈值是**看得见**的，改没改一眼就知道。
**别为了让 check 变绿去调阈值** —— 阈值是纪律的表达，不是它的反义词。

## 5. 它能看到什么、看不到什么（诚实清单）

**能**：同一帧里有几块字、哪块在主体区里、主体之外还有几个"看的地方"。
数据来源是**实际发生的绘制**（`gl.paint.blocks`，由 `src/core/text.js` 的 `noteText` 记下来），
**只看场景自己那一层** —— 引擎的字幕层 / HUD 层 / 错帧卡片画在别的图层上，天然不算进去。

**不能**：
- **看不出"一块字被别的元素盖住"** —— 它不读像素；那是"元素互相遮挡"的另一半，靠人眼看图；
- **看不出 3D 几何、矢量图形、面板边框**：只数**文字块**。所以"一屏 5 个面板 + 1 行字"它不会响。
  它只能**报一个总数**（"这一帧画了 N 次非文字绘制"，见 §1 的「主体区 0 块」）——
  `paint` 只记次数、**不记坐标**，所以"那 5 个面板在哪里"这一层答不出来；
- **看不出"这一块字该不该在"**：读数面板本身没错，错的是"一次全亮"。判据只能说"块太多"。

## 6.5 竖屏（1080×1920）的标定（2026-10-26，BACKLOG 1-52）

判据本身**不跟着画幅改**（`maxBlocks` / `maxOffSubject` / `maxInFocus` 数的是"看的地方"，
与画幅无关），但几何量（主体矩形、字幕带）必须按画幅换一套。做法写在
`src/style/index.js` 的 `fitStyleToFrame()`：`H > W` 时把栅格换成 `GRID_PORTRAIT`（1080×1920 基准、
按 **短边 = 宽** 缩放），字号阶梯 ×1.35。

实测（夹具 `tasks/_portrait-lab/`，`flat` 风格、两段、1080×1920、开字幕）：

```sh
node scripts/anim.mjs check _portrait-lab
# 版面守门：2/2 段采到了文字绘制 · 最挤的一帧 4 块（上限 6；主体之外 ≤ 2）
#   hero  t=1.05s  4 块  主体区 0 块字（主体是图形：2 次非文字绘制；4 块字全是标注）
#   bars  t=7.60s  3 块  主体区 0 块字（同上）
# 节奏（静态）：CoV 0.39  ·  ≥ 0.25
# 单帧 0.097 / 多子帧 0.097 —— 两条路径一致
```

**结论：竖屏不需要放宽阈值。** 第一版夹具确实触发过两次 ——
① 三个读数分开写（34 / 62 / 88）被数成 3 个"看的地方"；合并成一行后降为 1 块
（`labelRow` 那条纪律，竖屏比横屏更要紧：窄画幅里三个数就是三处视线）；
② 读数写在柱子基线下方，正好压进字幕带上沿 —— 改成写在柱顶上方。
两条都不是"阈值太严"，而是**画面本身该改**。

**只有一个数字是竖屏专属的**：`contentBottom`（1112）必须小于 `captionBand[0]`（1180）——
正文越过去就会被字幕底衬压住，而横屏的 900 < 40 那条关系是反的（横屏字幕在**顶部**）。
