## 0. 怎么用这份模板（**谁写、谁读、放在哪**）

```
主代理                                子代理（2–4 个，每个 2–4 段）
 ① 先自己写好 2 个"钉子"参考场景（一个 3D 范本 + 一个 2D 面板范本）
 ② 把这份模板复制成 tasks/<任务名>/SCENE-BRIEF.md，填掉全部占位符（填不出来 = 还没想清楚）
 ③ 派人 ────────────────────────────▶ ④ 先读 §1 的三份东西 → ⑤ 只写自己负责的 scenes/<段名>.js
                                       ⑥ **不跑任何渲染命令**；离线自查走 §9.1
 ⑧ 跑 check / still / video（主代理统一调度）◀─ ⑦ 交作业：3–5 行说明 + 查过哪些帧
```

- **谁写 brief**：**主代理**。子代理不许改 brief、不许改 §1 列的参考场景、不许改 `task.config.mjs`。
- **放在哪**：`tasks/<任务名>/SCENE-BRIEF.md`（跟着任务走，不会被 `anim clean` 清掉）。
  子代理要并行读、又怕渲染期写文件踩到 Vite，可以**先**落在 `out/_staging/`
  （`out/**` 是唯一被实测挡住文件监听的地方，`AGENTS.md` §7），**渲染完再搬进 `tasks/`**。
- **一份 brief 只管一支片子**。跨片子的部分（确定性铁律、事实纪律、字幕分工）**不要抄第二遍** ——
  引用 `AGENTS.md` / [`docs/CAPTIONS.md`](./CAPTIONS.md) 的章节号就行。抄第二遍就会分叉。

**填写清单（没填完就是没想清楚）**：

| 占位符 | 在哪一节 | 谁来定 |
|---|---|---|
| `<任务名>` `<片子标题>` `<总时长>` `<段数>` | 头部 | 主代理 |
| `style: '<风格名>'` + `captions: true/false` + `<上一支任务名>` 与差异对照 | §5 | 主代理（**风格由内容决定**；对照表见 §5，同味风险是提示不是门） |
| 1 份 API 文件 + 2 份参考场景的路径 | §1 | 主代理（**本片最重要的三份输入**） |
| 段时刻表（段名 / 起点 / 时长 / 放慢 / internal / 身份色） | §8 | 主代理（旁白算完就有） |
| 事实纪律的"不能写什么"清单 | §7 | 主代理（从 `FACTS.md` 抄） |
| **画面文字表** | §6 | **子代理**填自己那一段，主代理复核 |

## 2. 场景文件的形状（照抄这个骨架）

```js
// @ts-check
/** <段名> —— <一句话说清这一镜在讲什么>。
 *
 * 内部时间线（`t`，段内秒；整段 internal = <填你这一段的 internal>）：
 *   0.6  …  1.8  …   ← 逐条写清楚"第几秒画面上发生了什么"，和旁白的 cue 对齐
 *
 * 事实：<这一镜每个数字的出处，见 tasks/<任务名>/FACTS.md>；视觉决定：<见 §4>
 * 画面文字：<见 §6 的表；只写标注，不复述旁白>
 */
import { css } from '../../../src/core/util.js';
import { /* …从本片 API 文件按需 import… */ } from './<本片 API 文件>.js';

export default {
  id: '<段名>',
  render(ctx) {
    const { f, gl, lines, text, type, comp, P } = ctx;
    const t = <段内内部秒>;                  // ← 永远用它，不要直接拿 f.lt
    const cam = <本片摄影机>(f.t);            // ← 全片一台连续摄影机，永远用它

    gl.clear(ctx.out, [P.ink[0], P.ink[1], P.ink[2]]);   // 背景（声明了 world:'auto' 时由引擎铺）

    lines.begin();                            // ── 3D 层 ──
    /* …画世界… */
    lines.flush(ctx.out);                     // ← 必须 flush，否则后面的线画不出来

    text.clear();                             // ── 屏幕层（面板 + HUD + 标注）──
    lines.begin();                            // ← 不清字，上一帧的字会叠上来
    /* …标注、面板、段标签… */
    lines.flush(ctx.out);
    text.upload();                            // ← 忘了这句字全不见
    comp.draw(gl, text, ctx.out, { premult: false });

    return { /* 这一帧的 post */ };
  },
};
```

`text` / `type` / `lines` / `comp` 的完整生命周期见 `docs/ENGINE.md` §5 / §6 / §7，**不要在这里抄第二遍**。

## 3. 铁律（违反会随机出错，而且通常**不报错**）

> 完整版在 `AGENTS.md` §4。这里是**写场景时最常踩的九条**，写之前扫一眼。

| 禁止 | 为什么 | 正确做法 |
|---|---|---|
| `Math.random()` | 一帧拆成多个子帧乱序渲染，每子帧都调一次 → 抖动 | `ctx.rng(seed)` 在 `setup` 里预算，或用本片 API 的确定性哈希 |
| `Date.now()` / `performance.now()` / `new Date()` | 时间只能来自 `f.t` | 用 `f.t`（整片秒）/ 段内内部秒 |
| 逐帧累积（`this.x += v`） | 可任意 seek，累积值无意义 | 把位置写成**时间的函数** |
| 屏幕元素随 `f.idx` 抖 | 子帧之间会双重曝光 | 面板一律**静止**；要动就用 `t` 的平滑函数 |
| 交叠期里出字 | 引擎默认对交叠段做**交叉溶解**，两屏字会糊成一团 | 文字从 `sat(t / 0.5)` 起步（前 0.5s 是交叠期） |
| `lines.flush()` 之后又 `lines.seg(...)` | 画不出来（本引擎最常见的"东西不见了"） | 所有线在 `flush` 之前画完 |
| 忘了 `text.clear()` / `text.upload()` / `comp.draw` | 字叠帧 / 字全不见 | 见 §2 骨架 |
| **声明了 `handlesTransition` 却不铺整帧背景** | 那一段的底是**纯黑**，而且不报错 | 用 `world: 'auto'` 让引擎铺，或自己画一次全屏 Pass；`anim check` 的背景守门会报出来 |
| **把旁白的句子写进画面** | 观众看到"两条字幕"（[`docs/CAPTIONS.md`](./CAPTIONS.md) §1） | 画面只放**标注**：名词 / 数字 / 单位 / 出处 |

**另外五条口径**：① 场景对象可以有 `setup(ctx)`（只调一次，可 `async`），`render(ctx)` 每帧调。
② `ctx.P` 是调色板（**线性值**），给 Canvas2D 文字必须包 `css(...)` —— ⚠ `css()` **只吃两个参数**：
`css(col(P, name), a)` 对，`css(col(P, name, a))`（把 4 元组塞进去）**alpha 会被静默丢掉**
（上一轮 13 处踩了，`docs/history/IMPROVEMENTS-4-5.md` §2）。
③ 面板底色默认够不透明（0.9），**别调低**；**压暗用颜色（tone）不用透明度（alpha）** ——
「**alpha 管'在不在'，tone 管'亮不亮'**」（同文 §4.3），把 `alpha` 降到 0.4 得到的是"整片世界变成玻璃"。
④ **版面有六条带，其中 `sub`（字幕保留带）是引擎独占的**：说明条用 `captionNote()`、段标签用
`shotTag()`/`kicker()`、页脚用 `footer()`，坐标从带里取，**别手抄 `128, 964` 这种魔数**；
自查 `assertInBand(name, x, y, ctx, size, width)`。
⑤ **顺序**：线在 `flush` 之前画完；`text.upload()` 之后才 `comp.draw`。

## 4. 分级：什么是**硬约束**，什么是**本片自己的视觉决定**

> **这一节是这份模板相对原型改动最大的地方。** 原型的 §3 标题是「视觉语言（全片统一，**照这个来，不要自创**）」
> —— 那句话把**两类完全不同的东西**混成了一条命令：真正该钉死的（确定性、事实纪律、字幕分工）
> 被埋在一堆颜色值里，而真正该自创的（配色、构图母题、元件选择）被一起禁掉了，于是每支片子长得都像上一支。
> **现在分成两级。** 写场景之前先确认你**没有**违反 A 级；B 级你尽管自创，但**要写进 brief**。

### A 级 · 硬约束（不可协商，违反就是 bug）

| # | 约束 | 出处 |
|---|---|---|
| A1 | **确定性铁律** —— 每一帧是 `f.t` 的纯函数，见 §3 全表 | `AGENTS.md` §4 · `docs/ENGINE.md` §1 |
| A2 | **事实纪律** —— 画面里每一个数字都要有出处，见 §7 | [`docs/FACTS-TEMPLATE.md`](./FACTS-TEMPLATE.md) |
| A3 | **字幕分工** —— 旁白说句子 / 字幕显示这句话 / **画面只做标注，不复述旁白** | [`docs/CAPTIONS.md`](./CAPTIONS.md) §2 |
| A4 | **片内一致** —— 一支片子只用一套风格（一个 `style`） | [`docs/STYLE.md`](./STYLE.md) §6 纪律一 |
| A5 | **版面条带不许越界** —— 字幕保留带（`sub`）别人不许进；正文不越过 `contentBottom`(900) | [`docs/CAPTIONS.md`](./CAPTIONS.md) §4 |
| A6 | **只交你负责的文件** / **不跑渲染命令**（渲染由主代理统一调度） | §9 · `AGENTS.md` §7 |
| A7 | `flush` 之前画完所有线 / `text.clear()`+`upload()`+`comp.draw` / 交叠期不出字 | §3 表 |

### B 级 · 本片自己的视觉决定（**允许并鼓励自创**，但必须写进 brief）

| # | 可以自己定 | 在哪写清楚 |
|---|---|---|
| B1 | **配色**：身份色怎么分、中性色用哪几个、警告色什么时候出现 | §5.2 的"身份色"表 —— **本片自己排，不要抄上一支的** |
| B2 | **构图母题**：这一段的视觉主角是什么、在画面哪个位置、怎么入场 | §6 的"视觉主角"列 |
| B3 | **元件选择**：用哪几个元件、怎么组合、哪些是这一片特有的 | §1 的 API 文件 + 本片 `scenes/_kit.js` |
| B4 | **两层的比例**：3D 世界与 2D 面板各占多少、什么时候压暗谁 | §5.3 的"两层分工" |
| B5 | **背景母题**：`style.motif`（`grid`/`blueprint`/`paper`/`scan`/`noir`）或自己写一个 Pass | [`docs/STYLE.md`](./STYLE.md) §8 |
| B6 | **片内的小节奏**：这一段的"换气"放在第几秒 | [`docs/STYLE.md`](./STYLE.md) §7.7 |

**边界在哪**：B 级自由的前提是**不改 A 级**。你可以把面板做成斜的、把身份色换成朱红、
让世界在 3.0s 时翻过来（B 级）；但不能因此让同一段在两次渲染里长得不一样（A1），
也不能把旁白的句子抄到面板标题上（A3）。

## 5. 与上一支的风格对照（提示同味风险，**不是门**）

> **风格由内容决定**（[`docs/STYLE.md`](./STYLE.md) §6 纪律二）：先按这支片子的内容选最合适的风格；
> 下面这张表是把「和上一支哪里一样、哪里不一样」摆出来看 —— 同味风险是**提示**，没有"必须换几项"的硬性要求。
> **上一支片子**：`tasks/<上一支任务名>/`，它的 `task.config.mjs` 里写的是 `style: '<上一支的风格名>'`。

| # | 换什么 | 本片写什么 | 上一支是什么 | 换了吗 |
|---|---|---|---|---|
| ① | **主色 / 介质**（`style` 名） | `style: '<本片风格>'` | `<上一支风格>` | ☐ |
| ② | **字体**（`style` 自带或 `style.fonts` 覆盖） | `<本片字体取向>` | `<上一支字体>` | ☐ |
| ③ | **背景母题**（`style.motif`，或自写 Pass） | `<本片母题>` | `<上一支母题>` | ☐ |
| ④ | **每段的视觉主角**（不进风格包，见下） | 见 §6 表 | `<上一支的主角们>` | ☐ |

**如果两支连着发布且题材相近，同味的第 ④ 项（视觉主角）最值得换 —— 颜色字体全换了、主角还是"一叠方块+一个面板"，观众照样觉得是同一支。**

### 5.1 ① 主色 / 介质，顺带把字幕开关也定下来

```js
// tasks/<任务名>/task.config.mjs
style: '<本片风格>',      // print / blueprint / paper / terminal / noir —— 说明见 docs/STYLE.md §3
captions: true,           // 有旁白就打开引擎字幕层；场景里一个字都不用写
```

**不要**在本片内部混第二套 `style`（A4）。想先看效果：

```sh
node scripts/anim.mjs styles
node scripts/anim.mjs still _style-sampler -t 1.8,6,9.6 --style paper    # 临时覆盖，不改文件
```

### 5.2 ②③ 字体与背景母题

- **字体**：先看风格包自带的是什么（`terminal` 是**全片等宽**），不够就 `style: { name: '…', fonts: { serif: … } }`。
- **背景母题**：`motif` 只对**手写场景 + `world: 'auto'`** 那条路有效 —— A 档镜头模板自带背景，
  `motif` 换不掉它（[`docs/STYLE.md`](./STYLE.md) §8）。本片如果要换母题，就在 §1 的 API 文件里
  写清楚"背景是谁铺的"。

### 5.3 ④ 每段的视觉主角 —— 怎么把"观感"翻译成几何

`docs/history/IMPROVEMENTS-4-5.md` §7 有一条**最值钱**的教训：

> **用户的眼睛是量具，但要把观感翻译成几何。** 「不够直观」→ 拆成可验证的三条：
> ① 同屏元素太多（27 节 → 18 节，多数镜头只画 9 节）② 物件读不出体积（面朝向判据反了 + 排线缝）
> ③ 没有主角（`hero` + tone 分档）。**翻译完才能动手**；停在"感觉不够直观"上，改十版也改不对。

所以 §6 的表格里**每一段都要填"视觉主角"**，而且必须是**具体的几何**，不是形容词：
「画面要清楚」✗ → 「同屏只画 9 节；主角那一节 `hero: {i,j,k}`，其余 `tone × 0.22`」✓；
「要有层次」✗ → 「世界压到 `tone × 0.3` 当背景，面板走前台（`alpha` 不变）」✓；
「节奏快一点」✗ → 「3.0s 世界翻面、6.2s 面板入场 —— 这一段的一次换气在 6.2s」✓。

## 6. 画面文字表（每段必填，**子代理填自己那一段**）

> **两件事必须在这一节做完**：① 列出这一段画面上会出现的**文字**，并确认每一处都是**标注级**
> （名词 / 数字 / 单位 / 结构 / 出处），**不是句子** —— 判据见 [`docs/CAPTIONS.md`](./CAPTIONS.md) §2；
> ② 跟**这一段自己的旁白**做一次重复检查（§6.2）。

| 段名 | 视觉主角（几何描述） | 画面文字（**标注级**） | 落在哪条带 | 与旁白的关系 |
|---|---|---|---|---|
| `<段名 1>` | `<主角是什么、在哪、怎么入场；这一段的"换气"在第几秒>` | `<名词 / 数字 / 单位 / 出处>` | `<tag / hudR / caption / foot / title>` | `<标注自旁白的哪个名词或数字；写明"不复述">` |
| `<段名 2>` | … | … | … | … |

**视觉换气（每段至少一次）**：每 **20–40 秒**观众应该感到"换了个东西在看"（[`docs/STYLE.md`](./STYLE.md) §7.2）。
我们的段长通常 15–27 秒，所以**段内**至少要有一次"版面换气"：世界压暗 → 面板上台 / 面板退场 →
世界回来 / 一个新元件入场。**在表里"视觉主角"那一列写清楚它在第几秒发生。**

### 6.1 六条带（谁占哪一块）

数值以 `src/kit/bands.js` 的 `bands()` 为准；完整表（含算式与 1920×1080 下的实值）见

### 9.1 ✅ 可以做的**离线自查**（零渲染、零 GPU、渲染跑着也能跑）

```sh
node tools/scene-harness.mjs <任务名>                     # 跑全场 + 静态扫描 + 确定性比对
node tools/scene-harness.mjs <任务名> --scene <段名>       # 只查你那几段
node tools/scene-harness.mjs <任务名> --times 0.5,3,7.5    # 指定时刻；-v 详细
node tools/lint-narration-dup.mjs <任务名>                 # 画面文字复述旁白（§6.2）
```

`scene-harness.mjs` 用一套**假 ctx** 把你的场景在 Node 里跑一遍，它查五类（都不需要 GPU）：

1. **跑场**：`setup(ctx)` + 若干时刻 `render(ctx)`，任何抛错都点名到 `文件:行号`（未定义变量、类型错误、
   调了不存在的 API、拼错的字段）；
2. **确定性**：同一时刻连渲两遍，逐条比对绘制调用序列 —— 不一致 = 混进了 `Math.random` / `Date.now` /
   逐帧累积状态（再渲一遍"同 t、不同 `f.idx`"：序列不同只报**警告**，逐帧抖动是合法用法）；
3. **静态扫描**：`Math.random(` / `Date.now(` / `performance.now(` / `new Date(` / `Math.floor(t*60)` /
   `this.x +=`，给 `文件:行号`；
4. **数值健全**：NaN / ±Inf 出现在线坐标、文字坐标、post 返回值、**Pass 的 uniform** 里；
5. **骨架**：画了线没 flush、写了字没 clear/upload/comp.draw、交叠期没铺满整帧、线批超 6 万条被丢、
   文字出画、这一刻什么都没画。

**抓不到什么（诚实划界）**：shader 编译错误、**像素**（亮度/过曝/色彩/几何朝向/遮挡）、
真需要 GPU 的 `setup`（会跳过并说明）。那是 `still` / `check` 的活，**由主代理跑**。

② **`scene-harness` 的输出摘要**（过了没有、有没有警告），以及**你查过哪些帧、看到了什么**；

```text
   **查不到就写 `— 待确认 —`，不许编、不许推测**
4. 分段表（逐段分镜表，见 §11.5）：段 id / 时长 / **主体名词** / 屏上文字 / 运动一句话 / 拟用模板或 kit / 旁白要说的那一句
5. 每段的视觉母题：先用 `node scripts/anim.mjs shots` 里已有的模板，写模板名 + 参数；
   没有合适的写"要新写"，并说明为什么
6. 风格与字幕：`style` 名 + `captions` 开不开 + 与上一支的同味风险自查三项（§5）
7. anti-list：这支片子**不要**什么（自拟片头 / 进度条 / 把旁白抄上画面 / 复用上一支的元件…）

产出后**停下来等作者审**：不要开始写场景代码、不要跑渲染、不要在渲染期写仓库里的任何文件。
```

### 11.3 判据（作者只审 brief 就能开工）

- 第 3 块里**没有一个"看起来合理"却查不到出处的数字**（查不到就该是 `— 待确认 —`）
- 第 4 块每段的"视觉主角"能用**一个名词**说清（说不清 = 这段还没想好，回池子）
- 第 5 块里"要新写"的段数 **≤ 2**（更多就说明模板库不够用 —— 该补模板，而不是硬写）
- 第 7 块 anti-list **≥ 3 条**

### 11.4 与其它节的关系（只组装，不新增规则）

| 来源 | 用在哪 |
|---|---|
| §2 / §8（场景形状 / 段时刻表） | 第 4 块的分段表形状 |
| §7（事实纪律） | 第 3 块的事实骨架 |
| §5（风格对照） | 第 6 块的同味风险 |

### 11.5 分镜三件套（C2）：写场景前先对齐意图

brief 的第 4 块分段表，从「段 id / 时长 / 视觉主角 / 旁白」升级成**逐段分镜表**，每段五列：

| 段 id | 时长 | 主体名词 | 屏上文字 | 运动（一句话） | 拟用模板 / kit |
|---|---|---|---|---|---|
| hook | 4s | 镜组 | 穿过镜头 | 摄影机向前穿 | makeThreeShot |

**固化的协作顺序**（别跳步）：

1. **分镜表**：brief 里先把上表填完（主体能用一个名词说清，说不清 = 这段没想好）。
2. **placeholder 时间线**：每段先用 `shot('placeholder', { subject, onscreen, motion, ref })` 占位
   （配置档写 `{ type: 'placeholder', subject, onscreen, motion, ref }`）。它是网格底占位卡，不是成片。
3. **`anim board <任务>` 确认**：每段抽一格 + 「id · 时长 · note」标注，出 `out/<任务>/board.png`，
   用 Read 看图确认结构/节奏对，再往下走。
4. **逐段替换为真镜头**：把 placeholder 一段段换成真模板/手写场景。`check` 见到时间线里还有
   placeholder 会 warn（`--strict` 进 errs）—— 全换完才算交付。

> `placeholder` 的 `energy: 'none'`、`fits` 恒 false ⇒ `anim shots --pick` 永远抽不到它；它只用于分镜占位。
