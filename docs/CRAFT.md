# CRAFT —— 讲解片的画面手艺（从「不出错」到「第一版就好」）

> **为什么需要这份文档**：`anim check` 只守地板（不黑屏、不 NaN、不越界）。把 `check` 全绿当成做完，交出来的第一版就会像 [`docs/BAR.md`](BAR.md) 里的反面样本——代码没错，画面却空、平、像挂在黑板上的 PPT。
>
> **一条原则**：这里不写「要大气 / 要高级 / 要有科技感」这类形容词；**每一条手艺都落到几何比例、像素/字号数值或必须调用的引擎能力上**。

---

## §1 概念 → 画面：不靠旁白也看得懂

讲解片最常见的偷懒，是**先写旁白，再在屏幕上画个框把名词和标题放进去**。观众闭上耳朵只看画面，看到的是一页页大字报。

**动手写代码前，必须把每个抽象概念翻译成「不听声音也能看懂的物理/几何关系」**：

| 抽象概念类别 | 偷懒写法 ✗ | 几何/视觉翻译 ✓ | 例子 |
|---|---|---|---|
| **数量级 / 尺度** | 画一根均分直线标出两个数字 | 按真实比例或明确的对数标尺做视觉压缩；用物体半径/面积差承载倍数 | `light-seconds` ✗：「一条线加月球/太阳两个圆点」→ ✓：「左侧地球-月球真实比例尺 + 连续光脉冲波前推进 + 占满半屏的太阳圆盘/光晕对比」 |
| **机制 / 内部原理** | 写三行要点文字或画几个静态方块 | 用剖面图、三维拆解（`deconstruct`）、坐标变换或输入→输出实时算出的过程 | 讲色彩空间混合：✗「写出 sRGB 公式卡片」→ ✓「GLSL 实时算出同一组色块在 sRGB / Linear / Oklab 下的渐变带与亮度曲线对比」 |
| **比较 / 差异** | 左右两张独立卡片各写几行字 | 同一个参照物、同一组采样点并置，**只变正在对比的那一维**（色差线、误差柱、波形叠合） | 同一对颜色左右半屏或上下并行条带对比，中间拉出亮度偏差曲线 |
| **变化 / 因果** | 旧元素淡出，新元素淡入（opacity 0→1） | **动作触发结果**（`reveal` / `cascade` / `transform`）：波前扫过才点亮刻度，碰撞/遮挡揭开新层 | 接力物（如一根基准轴/扫描光标）从上一镜带到下一镜并触发显影 |
| **总结 / 收束** | 居中大字写一句感叹句 | 把前几段拆开来的元素收拢成一个完整系统或回到开场视觉母题，给出明确的最终读数/对比 | 开场的未解难题，在收尾由同一个母题在正确空间下一次性算对并定格 |

## §2 构图、占比与三层深度

一屏画面不只是「字放得下、不重叠」，还要**空间站得住**：

1. **主体占比 30%–60%**：每段只能有一个视觉主角（`focus`），它在 1920×1080 画幅里的包络面积占 **30%–60%**。小于 20% 像茫茫太空里飘着一个标点（如 `light-seconds` t=10）；大于 75% 且贴边则无处放标注与呼吸。
2. **空白格子占比 ≤ 55%（16×9 网格）**：把 1920×1080 切成 16×9 共 144 格（每格 120×120px）。如果超过 **55%（≈ 80 格）** 与背景底色几乎无差（格内亮度标准差 < 0.02 且均值贴近背景众数），就属于「画面空洞」（`CRAFT-EMPTY`）。留白必须是集中且有方向的负空间（例如左图右文留出的引导区），不是「主体只占屏幕中央一小块、四周全空」。
3. **三层深度（缺一层就平）**：
   - **背景世界层**（亮度压到主体的 **≤ 0.25**）：全片统一的 `world`（`grid` / `blueprint` / `paper` / `scan` / `noir` / 自定义 shader），由整片时间 `f.t` 驱动。
   - **中景主体层**（亮度 **1.0**）：本段的核心图形、3D 模型或实时 shader 可视化。若需要把世界当底压暗，**调低颜色亮度（tone），不要把前景面板 alpha 调成半透明玻璃**（见 `SCENE-BRIEF-TEMPLATE.md` §3）。
   - **前景标注层**（亮度配角 **≤ 0.5**，关键标注 **0.8–1.0**）：落在 [`src/kit/bands.js`](../src/kit/bands.js) 规定的六条安全带内，与主体拉出引线或明确边距，**绝不压住主体的关键几何或压进 `sub` 字幕保留带（默认 y 40–104）**。
4. **版面纪律参照**：一屏只看一件事、主体之外最多两块、字压字/出画/撞字幕判据详见 [`docs/LAYOUT.md`](LAYOUT.md) §1–§2.5 与 [`docs/CAPTIONS.md`](CAPTIONS.md) §2/§4，本文不重复。

## §3 视觉层级：字号、字族与明暗

1. **同屏最多 3 档字号**：例如 `hero`（核心标题或大数字）+ `body`/`h2`（次级说明）+ `label`/`mono`（单位、出处、眉标）。不要出现 4、5 种随手填出来的像素字号。推荐直接用风格包的语义字号（`'hero' | 'h1' | 'h2' | 'body' | 'label' | 'mono'`，见 [`docs/STYLE.md`](STYLE.md) §4.1）。
2. **主数字 : 标注字号 ≥ 2.5**：如果主读数是 `110px`，旁边单位/小标注应 ≤ `44px`（例如 `28–36px`）；比值小于 1.8 时，观众分不清哪一个是主角数字、哪一个是解释。
3. **数字与中文同一字族（或风格包显式配对）**：**禁止**手写 `'sans-serif'` / `'monospace'` 这种裸字体名（`CRAFT-FONT`）。统一调用 `type.write*` / `type.writeLine` 并传 `family: 'sans' | 'mono' | 'serif'`，让字体栈由 `ctx.style.fonts` 统一控制，避免「数字一种体、旁边中文另一种体」的割裂感。
4. **明暗三档**：
   - **主体**：线性亮度 **1.0**（或信号色 `P.signal` 点亮当前正在被讲述的那部分）。
   - **配角 / 辅助线框 / 次要对照**：**≤ 0.5**（例如 `mul(P.bone, 0.45)` 或 `P.ash`）。
   - **背景 / 刻度底网格**：**≤ 0.25**（例如 `mul(P.graphite, 0.25)`）。
   - **泛光红线**：只有信号色（高亮/发光/激活项）允许线性亮度 > 0.85 去触发 bloom；正文骨白永远不 bloom（`AGENTS.md` §5）。

## §4 运动分层：每一秒都要活着，但不能乱晃

一段合格的镜头不能只有「元素 A 从 0 滑到 1 后全程静止」。每段必须拆出**三层运动**：

| 层级 | 职责 | 常见写法 | 约束与出处 |
|---|---|---|---|
| **① 主动作** | 推进本段叙事、触发状态改变 | 弹簧到位 `spring`、三段推挤 `nudgeCurve`、因果显影 `reveal` / `cascade` / `transform`、shader 参数演化 | 有停顿有爆发，不能全程匀速漂移（`ANTI-PPT.md` C4/C7） |
| **② 次级跟随** | 陪衬主动作，拉出物理惯性与因果 | 错峰级联 `waterfallStagger`（总量 ≤ 0.5s）、指针/数值延迟回弹、引线从主体节点生长到标注 | 不能抢主角视线，总时长不可拖过主动作 |
| **③ 环境与摄影机** | 让画面作为连续空间存在，切镜不断 | 全片共享 `world(f.t)` 的微动 + `cameraPost(f.t)` / `operatorCam` + 平滑微呼吸 `shakeSmooth(f.t, amp)` | **严禁逐帧白噪声抖动**；其余参数与阈值上限全部以 [`docs/MOTION.md`](MOTION.md) §2–§3 为准，不在此重抄 |

- **静止上限**：任何 2 秒窗口都要有可见的构图或数值演进，最长静止跨度不超过 **3.5s**（`RULES.md` R1），但**也不要为了过检查而在角落画 2px 微光标**——补大面积推进、波前或连续视角移动。

## §5 高光时刻：每段只做一次真正揭晓

- **一个镜头只承载一个视觉峰值**：写进 `brief.mjs` 的 `segments[i].peak: { at, what }`，明确它在哪一秒（或对齐哪个旁白 `cue`）发生，以及画面在那一刻发生了什么不可逆的状态变化（例如「两条曲线在 x=0.5 处突然分叉并点亮误差面积」）。
- **避免平铺直叙**：不要 0.5s 把所有面板、曲线、标签一次性全亮出来，然后空讲 12 秒。信息应该按旁白节奏**分批由动作触发显影**，并在 `peak.at` 达到视觉焦点峰值。

## §6 必须用上的引擎能力（与 `lint-craft` 逐条对应）

绕开引擎能力直接裸写 Canvas2D 是第一版质量差的最快路径。以下是硬要求与机器扫描代码（见 [`tools/lint-craft.mjs`](../tools/lint-craft.mjs)）的对应关系：

| 引擎能力 | 必须怎么用 | 偷懒反例 | 对应检查代码 |
|---|---|---|---|
| **风格包字体** | 用 `type.write*` / `type.writeLine`，`family` 只写 `'sans' \| 'mono' \| 'serif'` | 在 `text.ctx.font` 里写死 `'sans-serif'` / `'monospace'` / `'serif'` | `CRAFT-FONT` |
| **风格包调色板** | 用 `ctx.P`（`P.bg` / `P.bone` / `P.signal` / `P.ash`）与 `css(P.x, a)` | 代码里大量写死 `rgba(...)` 或 `#hex` 字面量，超过 `P.` 引用数 | `CRAFT-COLOR` |
| **排版与动画层** | 一律走 `type.write` / `type.writeLine` / `type.reveal` / `labelRow` | 直接调 `text.ctx.fillText` / `strokeText` | `CRAFT-RAWTEXT` |
| **共享世界层** | 多段任务在 `task.config.mjs` 导出 `world` 并给段写 `world: 'auto'` | 多个各自为政的黑底场景，或只靠 `fillRect` 清纯色 | `CRAFT-NOWORLD` |
| **全片摄影机** | 用 `cameraPost(f.t)`、`makeShot`、`camera3` 或 `shakeSmooth` | 整片像固定机位幻灯片，全片零运镜 | `CRAFT-STATIC-CAM` |
| **分段与手写主角** | > 15s 的讲解片必须按叙事分段；主角段（hook / mechanism / close）手写 | 一整段撑满 20s（`CRAFT-MONO`），或模板段超过 40% / 同模板用 ≥ 3 次（`CRAFT-TEMPLATE`） | `CRAFT-MONO` / `CRAFT-TEMPLATE` |
| **空间填充与层级** | 合理布置主体尺度与三档明暗对比 | 16×9 空格 > 55%（`CRAFT-EMPTY`）；亮度 p95 − p5 < 0.25（`CRAFT-FLAT`） | `CRAFT-EMPTY` / `CRAFT-FLAT` |

> 注：静态/离线检查能抓到上述源码与像素级偷懒；另设 `CRAFT-TEXTONLY`（仅靠 `scene-harness` 的 `rec.stats` 统计零图形绘制段）视集成边界实现或留待后续完善（若未接线会在工具输出与文档中诚实标明，不假装已测）。

## §7 讲解片段型配方（及每类最俗的做法）

写 `brief.mjs` 时每段必须指定 `role`（`hook` / `mechanism` / `data` / `compare` / `close` / `bridge`）：

| `role` | 必选写法 | 推荐视觉结构 | 这个段型最俗的做法（严禁） |
|---|---|---|---|
| **`hook`**（开场钩子） | **必须手写**（`build: 'custom'`） | **第 1 秒直接抛反常现象或矛盾结果**：在共享世界里直接跑出一个反直觉视觉误差（如渐变带中间发暗/发紫），再引出核心问题 | 黑底居中大字标题淡入 + 副标题 + 一条横线生长 4 秒（典型模板片头） |
| **`mechanism`**（原理解析） | **必须手写**（`build: 'custom'`） | **分步拆解 + 因果动效**：把黑盒拆成 2–3 层可观测量（输入 → 空间扭曲/传递曲线 → 输出），用 GLSL Pass / 三维投影 / `makeShot` 动态演进 | 三个圆角卡片排一排，里面各写一段名词解释，箭头依次闪一下 |
| **`data`**（数据/量级） | 关键段手写，辅助段可用模板 | **尺度对比 + 动态采样**：坐标轴与刻度先铺世界，游标推着实际曲线或面积块展开，只在高光时刻亮出关键数字 | 柱状图从 0 长到 100%，顶上挂着 6 个同时亮着的大数字 |
| **`compare`**（对比） | 关键段手写，辅助段可用模板 | **同轴/同参并置**：两个方法共用同一输入（同一条横轴或色带），中间用高亮误差带/标尺直接量出差距 | 左边写「方法 A：优点/缺点」，右边写「方法 B：优点/缺点」两列清单 |
| **`close`**（收束） | **必须手写**（`build: 'custom'`） | **母题闭环**：把开场提出的视觉母题用正确机制重新走一遍并稳稳落定（`rest` 停稳），给出观众能记住的一句话结论与唯一核心数字 | 屏幕变暗后居中写出「感谢观看 / 总结：XXX 很重要」，然后缓慢淡出 |
| **`bridge`**（过渡/缓冲） | 可用配置档模板 | 镜头短平快（2–4s），靠 `relayTo` 把前一段的核心元素推向或变形为下一段坐标系（可用 `whip` / `kinetic` / `scan` 等模板） | 用 `mix` 交叉溶解硬切，没有任何接力物 |

## §8 首版防返工 6 条工程细则

来自 `tasks/oklab` 实测复盘的高频返工点——首版代码照这 6 条一次写对，直接省掉多轮返修：

1. **8.1 切点前主动归零 `zoomBoost` 与接力物位置（防 1 帧回弹）**：
   交叠期渲染时，引擎按时间线顺序由后一段覆盖合并前一段的 `post`（`post = { ...post, ...(ovObj ?? {}) }`）。若前段在高光 `peak` 处抬高了 `zoomBoost` 却没在切点前归零，到下一段首帧会瞬间弹回（例如 `0.022` 相当于 1920px 边缘单帧跳 `21px`）。
   动手写场景前先跑 `node scripts/anim.mjs cues <任务>` 拿精确的 `cutStartLt`，按下面写法在切点前主动归零（`railU` 等接力物位置同理）：
   ```js
   const zoomRelease = 1 - smoothstep(cutStartLt - 1.2, cutStartLt - 0.15, t);
   const zoomBoost = 0.022 * peak * zoomRelease;
   ```

2. **8.2 文字切换一律交叉淡化，禁用 `if (t < t0) A else B` 硬切**：
   硬切分支叠上 `spring` 或渐隐动画会在交界处闪出 3–5 帧重影（例如旧字未退净、新字已满亮叠在一起）。必须用同一过渡因子 `p = sat((t - t0) / 0.35)` 做 `1 - p` 与 `p` 交叉淡化（见 `tasks/oklab/scenes/close.js` `preSnapA` / `snap`）。

3. **8.3 `p15` 禁止空壳占位与剧透帧**：
   未登场的次级色带或对比面板在 `p15` 严禁提前画一个空心黑框占位等待；应通过 `smoothstep` 在登场时刻展开，开头先让当前正在讲的主角饱满铺满工作区（参见 `tasks/oklab/scenes/hook.js`）。同时，高光揭晓才该亮出的结论数字不要在 `p15` 提前剧透。

4. **8.4 同屏多图表 / 辅证严格同轴对齐**：
   主色带、曲线图、底栏对比格与全片底层母题标尺必须共享同一水平起止范围与中轴（例如全片统一 `x = 400..1760`，中心中轴严格对齐 `midX = 1080`），禁止各画各的导致视觉歪斜与散乱。

5. **8.5 运动模糊下动态数字读数用整帧时刻防重影**：
   开启 `samples=auto` 多子帧渲染时，连续时间 `f.lt` 驱动高速变化的小数字符串会导致 8 个子帧打出 8 个不同数字叠成模糊一团。数值字符串切换改用主帧整时刻驱动（图形/游标本身仍用连续 `f.lt` 保留物理运动模糊，参见 `tasks/oklab/scenes/oklab_mech.js`）：
   ```js
   const ltFrame = Math.max(0, Math.floor(f.idx) / f.fps - f.start);
   ```

6. **8.6 先跑 0.5 秒离线预检，再开 Chrome**：
   改完场景先跑 `node tools/scene-harness.mjs <任务>`（0.5 秒内同步检查铁律静态扫描、确定性、离线 `layout.guard` 与切点 `cut-zoom-jump`），全部清零后再跑 `anim check` / `anim review`。
