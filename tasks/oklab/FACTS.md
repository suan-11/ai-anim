## 1. 逐句与逐数标出处

| sRGB 编码值直接平均：红 `(255,0,0)` + 绿 `(0,255,0)` → **`(128,128,0)`**（`128,128,0` / **128**） | sRGB 编码空间算术平均：`0.5 × 255 = 127.5 ≈ 128`（归一化 `0.5`）。 |

| 线性光强平均 `0.5`（**50%** / 一半）重编码回 sRGB 约 **`0.7354`** → **`(188,188,0)`**（`188,188,0` / **188**） | IEC 61966-2-1 逆传递函数：`1.055 × 0.5^(1/2.4) − 0.055 = 0.735356...`；`0.735356 × 255 = 187.52 ≈ 188`。 |
| sRGB 近似伽马指数 **`2.2`** / 规范指数 **`2.4`**（分段阈值 `0.04045` / `12.92` / `0.0031308`） | IEC 61966-2-1 标准传输曲线（全曲线等效幂次近似 γ ≈ 2.2，分段公式幂次 2.4）。 |
| Oklab 三步变换：`M1`（线性 sRGB → LMS）、**立方根 `1/3`（`x^(1/3)`）**、`M2`（LMS' → `(L, a, b)`） | Ottosson (2020) `linear_srgb_to_oklab`：`l = 0.4122214708*r + 0.5363325363*g + 0.0514459929*b` 等；对 `(l, m, s)` 取立方根后乘 `M2` 得到 `(L, a, b)`。 |

| Oklab 红→绿中段切片动态读数口径：`L(u) = lerp(0.628, 0.866, u)`（`u ∈ [0, 0.5]`，按三位数实时显示至 `0.747`） | 场景 `oklab_mech` 滑动探针按数学线性插值公式逐帧计算得出，无虚构采样。 |

## 2. 刻意没写的东西及原因

| 没写的内容 | 为什么 |
|---|---|
| 「蓝和黄线性平均会撞出泥灰，只有 Oklab 才保真」 | **物理学与色度学上不成立**：纯蓝与纯黄是互补色，即使在 Oklab 直线插值下，经过连接两者的弦中点也接近中性灰；真正受 sRGB 伽马塌陷和 CIELAB 色相弯曲影响最直观的是「红+绿中点亮度塌陷到 0.214」以及「CIELAB 蓝到白发紫」。 |
| 具体的屏幕亮度尼特数或色域覆盖率百分比 | 与硬件校准和具体显示器面板有关，本片只讨论 sRGB/线性光/Oklab 的数学映射关系，不引用特定显示器厂商宣传数据。 |
| Display P3 / Rec.2020 的超色域裁剪细节 | 本片聚焦 sRGB 与 Oklab 感知插值原理，防止 90 秒短片信息过载。 |
